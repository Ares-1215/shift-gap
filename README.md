# 班次空檔分析（shift-gap）

上傳「運務通知（班次調整計畫）.docx」（內嵌班次表 Excel）或班次表 .xlsx，
找出每台車頭（曳引車／全拖車）**兩班之間停在同一站的空檔**與**收班後的待命時間**，
並依班表反推的站間車程列出「來回＋掛卸作業」放得進空檔的**鄰近站所**，
讓調度可以用在站空等的車頭跑加班，不必另叫車頭空趟過來。
再加上一份「加班需求清單」，就能把每條加班路線配到候選車頭。

- 網站：https://ares-1215.github.io/shift-gap/ （看板通行碼可看；上傳過的班次表存在網站，同事開網站就自動載入）
- 一鍵下載分析 Excel（說明／空檔_日期／站所別_日期／時間軸_日期／時段可用_日期／加班配車_日期／加班需求_日期／站間車程）

## 派車看板（首頁）

輸入時刻（或按「現在」）→ 依分區列出每站此刻在站空等的車頭：空到幾點、剩幾分、下一班去哪、剩餘時間跑得了哪些站來回；
剩餘 ≥60 分才算可用（可調），30–59 分標「即將出車」，跑完當天最後一班的標「收班待命」（終站≠起站的再標「需回起站」）。
站所卡片下方「預測加班」小表格：此刻起 2 小時內可能發車的路線、預估櫃數、常見發車時段、出現頻率（近 N 週有幾次）。
下方是站所 × 30 分時段（14:00 → 翌日 08:00）的可用車頭數熱圖，點格子切換時刻。
頁首的日期按鈕全站共用：日曆上有點的日子是網站上有班次表的，選了自動載入並切換看板、站所視角、車頭時間軸。
站所視角：依分區列出當天班次表出現過的全部站所（沒空檔的淡化顯示 0 筆，可勾「只看有空檔的站」），點站所看甘特圖與此刻在站；明細表預設收起。
給沒經驗的派車人員一眼看出「這個時間有哪些車頭可以用」。

## 規則

| 項目 | 說明 |
|---|---|
| 同場域 | 彰化＝秀水、中工＝西屯 視為同一地點（車程 0 分），空檔與車程都以場域計，顯示為「彰化／秀水」；參數列可改 |
| 非站所 | 工停＝外部停車場（台中市西屯區環中路三段 800 號），標「停車場」 |
| 可用車頭 | 該時刻在站空等且剩餘空檔 ≥ 門檻（預設 60 分） |
| 收班待命 | 跑完當天最後一班、後面沒班次的車頭仍視為在站待命可跑加班，預設算到翌日 08:00（可改固定分鐘或不計）；標「收班待命」。終站＝最後一個有站名的點，最後一班沒填時間時用車程推估到站並標「到站推估」 |
| 起站＝迄站 | 車頭當天應回到第一站（起站）；終站≠起站多半是誤輸，計算照資料在終站但加班後要回起站（可跑站所＝終站→目的站→起站、配車同理），標「需回起站／起迄不同，可能誤輸」 |
| 讀取範圍 | 只讀「曳引車」「全拖車」分頁；每台車頭 5 列（班次代號／附掛車廂／到離時間／到離站所／備註），續接列接在同一台 |
| 底色 | 白＝原班次、黃＝新增或調整、綠＝刪減（排除）。分析「調整後」班表 |
| 空檔 | 同車頭相鄰兩個時間點同站，停留 ≥ 門檻（預設 60 分）；跨午夜自動加一天 |
| 日初待命 | 空檔前沒有班次代號（報到後等出車／放空櫃等同站作業），預設排除、可勾選顯示 |
| 站間車程 | 由上傳班表實際班次「出發→到達」時間差取中位數（下限 5 分） |
| 可跑站所 | 去程＋回程＋作業緩衝（預設 30 分）≤ 空檔分鐘，由近到遠；括號為來回合計分鐘 |
| 加班配車 | A＝起站在站空等的車頭載去迄站再空回；B＝迄站在站空等的車頭先空去起站再載回來；可出發區間＝時間窗與空檔都放得下的發車時間；起迄同站（本站加班）以來回 60 分估 |

## 加班需求清單格式（CSV 或 Excel 第一張表）

必填「起站、迄站」；選填「日期(MMDD)、時間中位 或 時間窗起／時間窗迄(HHMM)、機率、等級、預估櫃數、常見班次、備註」。
只給「時間中位」時，時間窗＝前後 30 分；沒有時間＝全日。多份清單同時載入時，同一個日期以最新上傳的為準。

`tools/ot_forecast.py` 會從 nls 205「發送封櫃明細」的歷史加班／追加櫃產出這份清單（同星期近 8 週、自動剔除疑似假日、機率 ≥25% 分三級）：

```bash
python tools/ot_forecast.py 20261105 20261106 -o 加班預測_1105-1106.csv --weeks 8 --min 0.25
```

## 每日自動（Windows 工作排程 ShiftGap-Forecast）

每天 13:40（OpsHub-Daily 13:00 同步 205 之後）跑 `tools/daily_forecast.ps1` → `daily_forecast.py`：
1. 推測明天、後天的加班需求清單 → `桌面\運務\加班預測\加班預測_MMDD-MMDD.csv`（另存 `加班預測_最新.csv`）→ `push_to_site.ps1` 推到網站；
2. 若 `桌面\運務` 已有該日的運務通知 .docx 或班次表 .xlsx（檔名含日期），跑 analyze.py --needs 產出 `班次空檔分析_MMDD-MMDD.xlsx`，並用 `export_day.py` 轉成 JSON 推到網站（同一天覆蓋）。

紀錄在 `tools/daily.log`；漏跑會在下次開機補執行。手動：`python tools/daily_forecast.py --date 20261105 --days 2`。
Python 被擋時排程不會跑，但網站上傳與自動載入不受影響。

## 離線版（Python）

```bash
pip install openpyxl olefile
python tools/analyze.py "運務通知(班次調整計畫)(1105).docx" "運務通知_班次調整計畫_1106.docx" -o 班次空檔分析.xlsx --min 60 --buffer 30 --tail end --needs 加班預測_1105-1106.csv
# --tail end＝收班後算到翌日 08:00（預設）、--tail 180＝固定 180 分、--tail 0＝不計
```

`tools/parse_shift.py` 解析工作表，`tools/analyze.py` 計算與輸出，`tools/export_day.py` 把班次表轉成網站用 JSON；網頁 `index.html` 是同一套邏輯的 JavaScript 版本。
